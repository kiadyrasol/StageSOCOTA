\chapter*{Résumé}
\addcontentsline{toc}{chapter}{Résumé}

Ce rapport présente les travaux réalisés au sein du service IT du Groupe SOCOTA pendant la période du 10 août au 30 septembre 2026. La mission principale du stage a consisté à participer à la conception et au développement de \textit{GestionProjetSocota}, une application Web destinée à améliorer le suivi et le pilotage des projets de digitalisation.

La réalisation du projet a suivi plusieurs étapes. J'ai commencé par mettre en place un planning afin d'organiser le travail et les différentes phases de développement. J'ai ensuite réalisé la conception du projet et les diagrammes nécessaires avec Mermaid. Après cette phase, j'ai travaillé sur la base de données avec SQL Server, puis sur les différentes couches de l'application selon l'architecture Model--View--Controller (MVC).

L'application développée permet notamment de centraliser les informations relatives aux projets, de consulter leur état d'avancement et leur niveau de risque, de disposer de tableaux de bord, d'utiliser des vues Kanban, Roadmap et Gantt, de rechercher des projets selon plusieurs critères, d'importer des données provenant d'Excel et de gérer des éléments complémentaires tels que les RFC, commentaires, pièces jointes, historiques et notifications. L'authentification Windows et l'intégration avec Active Directory ont également été prises en compte.

Ce stage m'a permis de mettre en pratique mes connaissances en développement Web, en programmation C\#, en gestion de bases de données et en conception d'applications. Il m'a également permis de découvrir les différentes étapes nécessaires à la réalisation d'une solution informatique dans un contexte professionnel.

\textbf{Mots-clés :} gestion de projet, digitalisation, ASP.NET Core MVC, C\#, SQL Server, Entity Framework Core, IIS, Active Directory.

\chapter{Introduction}

\section{Contexte général du stage}

Le stage constitue une étape importante dans la formation d'un étudiant en informatique. Il permet de mettre en pratique les connaissances acquises pendant la formation, mais également de découvrir les méthodes de travail, les contraintes et les exigences d'un environnement professionnel.

J'ai effectué mon stage au sein du Groupe SOCOTA, dans le service IT, du 10 août au 30 septembre 2026. Durant cette période, j'ai participé à la réalisation d'un projet informatique ayant pour objectif d'améliorer le suivi des projets de digitalisation de l'entreprise.

Ce stage m'a permis de travailler sur plusieurs aspects d'un projet informatique. Il ne s'agissait pas uniquement d'écrire du code : il fallait d'abord comprendre le besoin, organiser les étapes de travail, concevoir la solution, structurer les données, développer les différentes fonctionnalités, effectuer des tests et préparer l'application à son environnement de déploiement.

\section{Présentation de la mission}

La mission principale consistait à participer au développement de \textit{GestionProjetSocota}, une application Web permettant de centraliser et de faciliter le suivi des projets.

Avant la mise en place de la plateforme, le suivi pouvait notamment s'appuyer sur des données regroupées dans un fichier Excel. Une telle organisation peut devenir moins pratique lorsque le nombre de projets et d'informations associées augmente. Il devient alors nécessaire de disposer d'une solution permettant de centraliser les informations et de proposer différentes représentations adaptées aux besoins des utilisateurs.

L'application développée répond à ce besoin en regroupant les données dans une base SQL Server et en proposant une interface Web permettant leur consultation et leur gestion.

\section{Problématique}

La problématique principale du projet peut être formulée de la manière suivante :

\begin{quote}
\textbf{Comment centraliser et améliorer le suivi des projets de digitalisation afin de disposer d'informations structurées, accessibles et exploitables par les différents profils d'utilisateurs ?}
\end{quote}

Cette problématique implique plusieurs besoins : centraliser les données, faciliter leur consultation, représenter les projets de plusieurs manières, sécuriser les accès et permettre aux responsables de disposer d'une vision synthétique du portefeuille.

\section{Objectifs du stage}

L'objectif général du stage était de participer à la réalisation d'une plateforme Web de pilotage des projets de digitalisation.

Les objectifs spécifiques étaient notamment :

\begin{itemize}
    \item analyser le besoin et le cahier des charges ;
    \item organiser les étapes de réalisation à travers un planning ;
    \item concevoir la structure générale du projet ;
    \item mettre en place la base de données ;
    \item développer l'application selon l'architecture MVC ;
    \item centraliser les informations relatives aux projets ;
    \item proposer plusieurs modes de visualisation ;
    \item mettre en place des tableaux de bord ;
    \item permettre l'import de données Excel ;
    \item gérer les commentaires, pièces jointes, RFC, historiques et notifications ;
    \item intégrer la gestion des utilisateurs, rôles et permissions ;
    \item prendre en compte l'authentification Windows et Active Directory ;
    \item tester les fonctionnalités et corriger les problèmes rencontrés ;
    \item préparer le déploiement de l'application Web.
\end{itemize}

\section{Méthodologie suivie}

La réalisation du projet a été progressive. J'ai d'abord étudié le cahier des charges et organisé le travail. Un planning a ensuite été établi afin de visualiser les différentes étapes.

La conception a été réalisée avec Mermaid. Cette étape m'a permis de représenter la structure du projet avant de commencer la réalisation technique.

Après la conception, j'ai travaillé sur la base de données, puis sur les Models, les Controllers et les Views. Les fonctionnalités ont été développées progressivement et testées au fur et à mesure.

Enfin, j'ai travaillé sur les aspects liés à l'authentification, aux rôles, à Active Directory et à la préparation du déploiement.

\section{Organisation du rapport}

Le présent rapport est organisé de manière à suivre l'évolution du projet. Après la présentation du Groupe SOCOTA et du service IT, il présente le contexte et les objectifs du projet. Il décrit ensuite l'analyse et la conception, les technologies utilisées et les étapes de réalisation de l'application. Les fonctionnalités sont ensuite détaillées à l'aide de captures d'écran. Enfin, le rapport présente la sécurité, les tests, le déploiement, les difficultés rencontrées, les compétences acquises et le bilan du stage.

\chapter{Contexte, analyse et cahier des charges}

\section{Contexte initial}

Le suivi des projets constitue une activité qui nécessite de maintenir des informations régulièrement mises à jour. Lorsque les informations sont regroupées dans un fichier Excel centralisé, leur exploitation peut devenir plus complexe à mesure que le portefeuille augmente.

Une application Web permet de proposer une approche différente : les données sont enregistrées dans une base structurée et les utilisateurs disposent d'interfaces adaptées à leurs besoins.

L'objectif n'était donc pas simplement de remplacer un fichier par une interface Web, mais de proposer un véritable outil de pilotage.

\section{Besoins fonctionnels}

Les principaux besoins fonctionnels identifiés sont les suivants :

\begin{enumerate}
    \item gérer les projets ;
    \item consulter les informations détaillées d'un projet ;
    \item modifier les informations selon les permissions ;
    \item visualiser les projets sous différentes formes ;
    \item suivre l'avancement et le risque ;
    \item disposer de tableaux de bord ;
    \item rechercher selon plusieurs critères ;
    \item importer des données Excel ;
    \item gérer les RFC ;
    \item ajouter des commentaires ;
    \item gérer des pièces jointes ;
    \item conserver un historique ;
    \item afficher des notifications ;
    \item gérer les utilisateurs et leurs rôles ;
    \item sécuriser l'accès à l'application.
\end{enumerate}

\section{Besoins non fonctionnels}

L'application doit également répondre à des besoins non fonctionnels :

\begin{itemize}
    \item proposer une interface claire et utilisable ;
    \item contrôler les accès selon les rôles ;

    \item permettre l'utilisation de l'authentification Windows dans l'environnement prévu.

\section{Acteurs et rôles}

La gestion des rôles permet d'adapter les possibilités offertes à chaque utilisateur. L'application comporte notamment des profils liés à l'administration et à la gestion de projet.

Cette séparation est importante car tous les utilisateurs ne doivent pas nécessairement disposer des mêmes droits. L'autorisation est ainsi associée aux fonctionnalités sensibles.

\chapter{Conception de la solution}

\section{Choix de l'architecture MVC}

L'application utilise l'architecture MVC, qui signifie \textit{Model -- View -- Controller}. Cette organisation permet de séparer les responsabilités de l'application.

Le \textbf{Model} représente les données et les entités manipulées par l'application. Il permet de définir la structure des informations utilisées par le système.

Le \textbf{Controller} reçoit les requêtes de l'utilisateur, effectue les traitements nécessaires et prépare les données qui seront envoyées à l'interface.

La \textbf{View} correspond à l'interface présentée à l'utilisateur. Elle permet d'afficher les données et de proposer les formulaires et actions nécessaires.

Cette séparation rend le projet plus organisé et facilite son évolution.

\section{Conception de la base de données}

La base de données a été réalisée avec SQL Server. Elle constitue le stockage central des informations de l'application.

Les données sont organisées autour des projets et des différentes informations qui leur sont associées. Le système prend notamment en compte les actions, commentaires, pièces jointes, RFC, historiques et notifications.

La conception de la base a constitué une étape importante car les relations entre les différentes informations doivent être cohérentes avec le fonctionnement de l'application.

\section{Accès aux données}

Entity Framework Core a été utilisé afin de faciliter l'accès à SQL Server depuis le code C\#. Il permet de représenter les données sous forme d'entités et de réaliser les opérations nécessaires sur la base.

Cette approche permet de conserver une séparation entre la logique applicative et les détails des requêtes SQL.

\section{Conception de l'interface}

L'interface a été conçue pour faciliter la consultation des informations. Bootstrap et AdminLTE ont notamment été utilisés pour structurer les pages et les tableaux de bord.

Une attention particulière a été portée à la cohérence visuelle de l'application, notamment avec l'utilisation de la couleur verte du projet.

\section{Conception des visualisations}

Le projet propose plusieurs visualisations complémentaires.

La vue \textbf{Kanban} permet une lecture par statut. La \textbf{Roadmap} permet une lecture temporelle du portefeuille. Le \textbf{Gantt} représente les périodes et échéances sous forme graphique.

Ces vues répondent à des besoins différents tout en utilisant les mêmes informations de base.

\chapter{Technologies et outils utilisés}

\section{C\#}

C\# est le langage de programmation principal utilisé pour le développement de l'application. Il a été utilisé pour réaliser la logique métier, les Controllers, les Models et différents services.

L'utilisation de C\# m'a permis de mettre en pratique les notions de programmation étudiées durant ma formation dans un projet réel.

\section{ASP.NET Core MVC}

ASP.NET Core MVC est le framework utilisé pour développer l'application Web. Il fournit l'environnement nécessaire pour organiser le projet selon le modèle MVC.

Il a été choisi afin de disposer d'une structure adaptée à une application Web organisée en Models, Controllers et Views.

\section{SQL Server}

SQL Server est le système de gestion de base de données utilisé pour stocker les informations de l'application.

Il a été utilisé car le projet nécessite une base relationnelle capable de gérer les projets et les nombreuses données qui leur sont associées.

\section{Entity Framework Core}

Entity Framework Core est l'outil utilisé pour faciliter la communication entre l'application C\# et SQL Server.

Il permet de manipuler les données sous forme d'objets et d'entités et simplifie les opérations de lecture et d'écriture.

\section{HTML, CSS et JavaScript}

HTML structure les pages Web, CSS permet de gérer leur présentation et JavaScript apporte des comportements interactifs.

Ces technologies sont complémentaires à ASP.NET Core MVC pour construire l'interface utilisée par les utilisateurs.

\section{Bootstrap}

Bootstrap a été utilisé pour faciliter la construction de l'interface et obtenir une présentation cohérente des composants.

\section{AdminLTE}

AdminLTE a été utilisé pour structurer l'interface de type tableau de bord et certains éléments de navigation.

\section{Mermaid}

Mermaid est un outil permettant de produire des diagrammes à partir d'une description textuelle. Il a été utilisé pendant la phase de conception afin de représenter le projet et de faciliter sa compréhension.

\section{Frappe Gantt}

Frappe Gantt a été utilisé pour produire la représentation graphique des échéances et des périodes des projets sous forme de diagramme de Gantt.

\section{Visual Studio et Visual Studio Code}

Visual Studio et Visual Studio Code ont servi au développement et à la modification du code source. Ils ont également été utilisés pour les tests et la vérification progressive du fonctionnement de l'application.

\section{IIS}

IIS (\textit{Internet Information Services}) est le serveur Web de Microsoft utilisé pour héberger des applications Web sur Windows Server.

Dans le cadre du projet, IIS constitue l'environnement envisagé pour le déploiement de l'application Web.

\section{Active Directory}

Active Directory est le service d'annuaire de Microsoft permettant notamment de gérer des utilisateurs, groupes et ressources dans un environnement Windows.

Dans le projet, Active Directory intervient dans le cadre de l'authentification Windows et de la gestion des accès.

\section{Pourquoi ces outils ont-ils été utilisés ?}

Les outils ont été choisis selon leur rôle dans les différentes étapes du projet. C\# et ASP.NET Core MVC constituent la base du développement. SQL Server et Entity Framework Core assurent la gestion des données. Bootstrap et AdminLTE facilitent la réalisation de l'interface. Mermaid intervient dans la conception, tandis que Frappe Gantt répond au besoin de visualisation du planning.

IIS et Active Directory répondent quant à eux aux besoins liés à l'environnement Windows prévu pour l'application.

\chapter{Sécurité, utilisateurs et Active Directory}

\section{Importance de la sécurité}

Une application de gestion de projets contient des informations qui ne doivent pas nécessairement être accessibles à tous les utilisateurs. La sécurité doit donc prendre en compte l'identification des utilisateurs et leurs droits.

\section{Authentification Windows}

L'authentification Windows permet à l'application de s'appuyer sur l'identité du compte Windows de l'utilisateur.

Dans un environnement professionnel configuré pour cette utilisation, l'utilisateur peut accéder à l'application avec son compte Windows sans avoir à gérer un système de mot de passe distinct pour l'application.

\section{Active Directory}

Active Directory permet de centraliser la gestion des comptes et groupes dans un environnement Windows.

L'intégration avec Active Directory permet donc de prendre en compte les utilisateurs de l'environnement de l'entreprise pour l'accès à l'application.

\section{Rôles et autorisations}

Les autorisations sont utilisées pour limiter certaines actions aux profils disposant des droits nécessaires.

Dans le code ASP.NET Core, l'attribut \texttt{Authorize} peut être utilisé pour protéger une fonctionnalité ou un Controller.

Par exemple :

\begin{lstlisting}[language={[Sharp]C}]
[Authorize(Roles = "Administrateur,ChefDeProjet")]
public class RFCController : Controller
{
    // ...
}
\end{lstlisting}

Cet exemple montre que l'accès au Controller peut être limité aux rôles \textit{Administrateur} et \textit{ChefDeProjet}.

\section{Principe du contrôle d'accès}

Le contrôle d'accès permet donc de distinguer l'identité de l'utilisateur et les actions qu'il est autorisé à effectuer. Cette séparation est particulièrement importante pour les opérations de création, modification ou administration.

Ce type de problème montre l'importance des tests dans un environnement réel et de la prise en compte des erreurs transitoires dans l'accès aux données.
